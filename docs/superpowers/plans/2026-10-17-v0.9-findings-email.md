# v0.9 Audit findings, corrective actions and email reminders — Implementation Plan

**Goal:** Findings raised from audit results with ISO grades and full CAPA (root cause, actions with
evidence, independent verification); a daily email digest per person through the organisation's own
mail server.

**Spec:** `docs/superpowers/specs/2026-10-17-v0.9-findings-email-design.md`

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, pytest (`uv`); React 19, TanStack Router/Query,
Tailwind, Vitest; `smtplib` and `cryptography` (Fernet), both already available.

## Global Constraints

- Tests and fixtures use invented text and addresses (`@acme.com`, `@example.com`).
- Commits: explicit paths (`git add <paths>`, never `-A`), author and committer
  `Hamza Younas <hamzavelous@gmail.com>`, no co-author or tool trailers.
- Backend checks: `cd backend && uv run ruff check . && uv run ruff format --check . && uv run pytest -q -W error -o addopts=""` (Python 3.12).
- Frontend checks: `cd frontend && npx tsc --noEmit -p . && npx vitest run`.
- The SMTP password never appears in an API response, the audit trail or a log line.
- Version 0.9.0 in `backend/pyproject.toml`, `backend/uv.lock`, `frontend/package.json`,
  `frontend/package-lock.json` (2 places).

## Review Focus

1. Lifecycle cannot be skipped: no closing a nonconformity without verification; no verification by
   the finding owner or an action owner; status follows actions automatically. (Task 2)
2. Raising from audits is idempotent under repeat clicks and the bulk call. (Task 3)
3. The digest never sends twice for the same person and day, skips opted-out and inactive people,
   and one bad recipient does not stop the run. (Task 6)
4. `ASSAYR_SECRET_KEY` is added on upgrade without touching existing values. (Task 7)

### Task 1: Models, migration 0013, permissions

- Tests: migration upgrade on a database with audits; RBAC matrix.

### Task 2: Findings API and lifecycle
- `findings/schemas.py`, `findings/service.py` (status derivation, eligibility), `findings/router.py`.
- Create/edit (manage, or owner for root cause/correction/response), actions (create by manage or
  finding owner; done by action owner with note or file), verify, close (observation/OFI), reopen
  (ISMS manager), raise-risk, list filters, summary.
- Tests: every transition and error message in the spec; permissions per role.

### Task 3: Raise findings from audits
- `POST /audits/{id}/findings` (`item_ids` or `all`); defaults by result; owner = control owner.
- Audit item output gains `finding: {id, code, status} | null` and `result_changed`.
- Tests: single, bulk, repeat (no duplicates), wrong result 422, row removed afterwards.

### Task 4: Action files, export
- Upload (store + ClamAV like documents), download, delete by uploader while open;
  `GET /findings/export.xlsx`.
- Tests: upload/download, EICAR rejected, export columns.

### Task 5: Mail settings, encryption, sending

- Tests: password write-only and absent from audit trail; missing key refusal; test email via a
  stubbed SMTP class; permission `settings:manage`.

### Task 6: Daily digest
