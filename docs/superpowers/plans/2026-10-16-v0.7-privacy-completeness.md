# v0.7 Privacy Completeness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add DPIAs, data subject requests, a breach register, a processor register, consent/retention fields and the PDPPL framework to Data privacy.

**Architecture:** Extend `assayr.privacy` with models (`Dpia`, `DpiaRisk`, `SubjectRequest`, `Breach`, `Processor`, `ActivityProcessor`), routers split per area (`dpia_router`, `requests_router`, `breaches_router`, `processors_router`, `pdppl_router`), a PDPPL data file + seeder + evaluator; one migration `0010_privacy_completeness`; role `privacy_officer`, permission `privacy:sensitive`. Frontend: Data privacy tabs (Overview, Activities, PII inventory, Requests, Breaches, Processors, PDPPL), DPIA section on the activity page, request/breach detail pages, PDPPL on Compliance/Dashboard.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, pytest; React 19, TanStack Router/Query, Tailwind v4, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-16-v0.7-privacy-completeness-design.md`

## Global Constraints

- No PDPPL text in the repo: own summaries; article hints marked "verify against the official text"; "guidance, not legal advice" shown on the PDPPL page and README.
- `privacy:sensitive` required for requests and breaches (privacy_officer, isms_manager); summary counts visible with `assets:read`.
- Settings: `privacy_dsr_days = 30`, `privacy_breach_hours = 72`.
- Codes: `DSR-001`, `PDB-001` per scope.
- DPIA recommendation: any two screening "yes", or `sensitive`/`children`/`automated` alone.
- Ratings use the shared five-level words and colours.
- Gates: backend `uv run ruff check . && uv run ruff format --check . && uv run pytest -q -W error -o addopts=""`; frontend `npx tsc --noEmit -p . && npx vitest run`. Explicit `git add`; no co-author trailers. Before each commit confirm `git branch --show-current` is `v0.7-privacy`.

## Review Focus

1. **A request received on 31 January** — due 2 March (30 days, calendar); overdue the next day; test in Task 3.
2. **A breach where notification is "not required"** — no countdown, no overdue flag; test in Task 4.
3. **Raising the same DPIA risk twice** — one register risk; test in Task 2.
4. **A viewer opening a breach or request** — 403; counts still in the summary; tests in Tasks 3–4.
5. **A processor with an agreement but no date, or ended processors** — PDPPL "processors" evidence ignores ended ones; test in Task 5.
