# v0.6 Asset CIA Levels, Personal Data and Data Privacy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Assets show C/I/A and criticality as Very low…Very high, record personal data (PII), and a new Data Privacy module holds the record of processing activities and an automatic PII inventory with Excel export.

**Architecture:** Asset levels stay integers (1–5) with `*_label` output fields; PII columns on `asset`; new module `assayr.privacy` (models `ProcessingActivity`, `ProcessingAsset`, schemas, router); one migration `0009_privacy`; permission `privacy:manage`. Frontend: asset form/list changes, shared `LevelBadge`, new Data Privacy pages.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, openpyxl, pytest; React 19, TanStack Router/Query, Tailwind v4, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-16-v0.6-data-privacy-design.md`

## Global Constraints

- Levels: `{1: "Very low", 2: "Low", 3: "Medium", 4: "High", 5: "Very high"}`; integers unchanged in DB and API input; criticality = max(C, I, A).
- Badge colours: Very low `--idle`, Low `--ok`, Medium `--warn`, High `--heat-4`, Very high `--bad`.
- PII categories and sensitive set exactly as the spec; sensitive auto-true when a sensitive category is present; PII fields cleared when `holds_pii` false.
- Lawful bases: consent, contract, legal_obligation, vital_interest, public_interest, legitimate_interest. Data subjects as the spec.
- Activity codes `PA-001` sequential per scope.
- Read needs `assets:read`; activity writes need `privacy:manage` (isms_manager); asset PII follows existing asset edit rights.
- Gates: backend `uv run ruff check . && uv run ruff format --check . && uv run pytest -q -W error -o addopts=""`; frontend `npx tsc --noEmit -p . && npx vitest run`. Explicit `git add`, no co-author trailers.

## Review Focus

1. **An asset whose PII flag is switched off** — categories, sensitive and volume are cleared, and it leaves the inventory; test in Task 1.
2. **Linking an asset from another scope or an unknown id to an activity** — 422, nothing linked; test in Task 2.
3. **Unknown category, subject or lawful basis values** — 422 with a clear message; tests in Tasks 1–2.
4. **An asset owner editing PII on someone else's asset, or a viewer creating an activity** — 403; tests in Tasks 1–2.
5. **Excel export with user text starting with "=" or "+"** — written as text (safe_cell); test in Task 2.
