# v0.3.1 — Maroon theme, new dashboard, Compliance page, risk owners — design

Date: 2026-10-15
Status: awaiting user review
Source: the user's requests on 2026-10-15 and `Dashboard Reference 1.jpeg` / `Dashboard Reference 2.jpeg`
(Vanta: framework rows with "X controls passing / Y total" bars; "Needs attention" monitoring cards).

## Goals

1. Brand: maroon **#8A1538** (RGB 138, 21, 56) and white, from the Qatar flag.
2. A dashboard that shows only the overall picture, clean and visual: compliance per framework (ISO 27001
   now, NIA when it exists, framework names in bold), partial progress visible (not "strict"), risk status
   (open / in progress / closed), trend line and charts in several colours.
3. Remove "Readiness by Annex A theme" from the dashboard.
4. A Compliance page in the Vanta style, reached from the navigation.
5. Assign a risk owner from the UI.

Out of scope: NIA data (v0.4), policies (v0.4), training (v0.5), new backend scoring rules.

## 1. Theme

Replace the blue primary in `frontend/src/styles/tokens.css`, light and dark:

| Token | Light | Dark |
|---|---|---|
| `--primary` | `#8A1538` | `#E0577C` (maroon lightened to pass 4.5:1 on the dark surface) |
| `--primary-hover` | `#6F102C` | `#EA7A98` |
| `--primary-soft` | `#F7E8ED` | `#3A1220` |
| `--on-primary` | `#FFFFFF` | `#1A0610` |

Surfaces stay white (`--surface`) on a light warm-grey canvas (`--canvas: #F7F5F6`). Status colours (ok, warn,
bad, review, idle) stay as they are: they carry meaning and must stay distinguishable from the brand colour.
A chart palette is added as tokens (`--chart-1..6`): maroon, teal, amber, slate-blue, green, grey — checked
for contrast and colour-blind separation. The login page, buttons, links, focus rings and the active nav item
all follow `--primary`, so the rebrand is a token change plus a sweep for hard-coded blues.

## 2. Dashboard (Home)

Top to bottom, modelled on the two references:

**Header:** "Welcome, <name>" and the date.

**Compliance** (reference 2): one row card per framework.
- Left: framework name in **bold** (e.g. **ISO/IEC 27001:2022**), a maroon progress bar, "43 controls
  compliant · 93 total" and the readiness percentage, large.
- Right: a stacked status bar and legend showing partial progress:
  compliant / in review / in progress / at risk / non-compliant / not started, with counts. This is the
  answer to "it is too strict": work under way is visible, not only fully compliant controls.
- Clicking the card opens the Compliance page.
- When v0.4 adds NIA, a second row appears with **NIA v2.1** in bold. No placeholder before then.

**Monitoring** (reference 1), three cards, each with a "Needs attention" number, a bar, "X OK · Y total"
and a link:
- **Evidence:** needs attention = evidence awaiting review + rejected + expiring/expired.
- **Risks:** open / in progress / closed counts as a three-part bar (mapping below).
- **Controls without an owner:** count, links to the Controls list filtered.

**Charts row:**
- **Readiness trend:** line chart of readiness over time (from the existing `/readiness` trend snapshots),
  maroon line, soft fill, hover shows date and value.
- **Control status:** donut of the six statuses, with the readiness % in the centre.
- **Risks by level:** bar chart of current risk levels (low → critical) using the heat colours already used by
  the risk heatmap.

Charts are small SVG components written in-house (no chart library): they work offline, follow the tokens in
light and dark mode, have text alternatives (each chart has a visually hidden table), and respect
reduced-motion.

**Risk status mapping** (risk statuses already computed by the backend):

| Dashboard | Risk statuses |
|---|---|
| Open | draft, assessed, review_due, reassessing |
| In progress | treatment_planned, in_treatment |
| Closed | treated, accepted, closed |

**Removed:** "Readiness by Annex A theme".

**Data:** existing endpoints (`/readiness`, `/controls/summary`, `/risks`, evidence review queue). One new
read-only endpoint `GET /api/v1/dashboard` returns all dashboard numbers in one call (framework rows, status
counts, evidence attention counts, risk status buckets, risk level counts, unowned controls), so the page makes
one request and the mapping lives in the backend with tests.

## 3. Compliance page

New nav item **Compliance** (replacing the current Compliance group heading being only a label) at
`/compliance`, Vanta reference 2 layout:
- One card per framework (ISO 27001 now), name in bold, progress bar, controls passing / total, readiness %.
- Under it, a breakdown list: each ISO 27001 clause group (4–10) and each Annex A theme (Organisational,
  People, Physical, Technological) with its own thin progress bar and "X / Y compliant". (The per-theme data
  that leaves the dashboard lives here.)
- Each row links to the Controls list filtered to that group.

## 4. Risk owner

- Risk detail page: the "Owner" line becomes a picker (searchable select of active people from
  `GET /api/v1/people`), with "Unassigned" as an option. Saving calls the existing
  `PATCH /api/v1/risks/{code}` with `owner_id`. Only users with risk-write rights see the picker; others see
  the name as now.
- Risk wizard, first step: an optional Owner picker; the new risk is created with that owner.
- Risk list: owner filter "Mine / Unassigned / anyone" (the API already supports `owner=me`); add
  `owner=none` for unassigned.

## Quality bar ("clean UI/UX")

- Follow the references' structure: generous whitespace, one card style (white surface, 1 px line, 12 px
  radius), clear hierarchy (section titles 18 px semibold, numbers large and tabular), no clutter.
- Responsive: cards stack on narrow screens; no horizontal scroll at 360 px.
- Accessibility: WCAG AA contrast in light and dark, keyboard focus visible (maroon ring), charts have text
  alternatives.
- Loading skeletons instead of empty jumps; empty states explain the next step ("Upload the first evidence to
  see readiness").

## Testing

- Backend: `/dashboard` endpoint tests (counts, risk-status buckets, unowned controls, permissions);
  `owner=none` filter.
- Frontend (Vitest + Testing Library): dashboard renders framework row, monitoring cards, charts' text
  alternatives, no "Annex A theme" heading; Compliance page groups; owner picker saves and shows the new owner;
  wizard passes the owner.
- Visual check in the browser in light and dark mode at desktop and phone width before release.
