# v0.5 — Training and awareness — design

Status: approved in conversation 2026-10-16. Builds on v0.4.1.

## Purpose

ISO/IEC 27001 A.6.3 and the matching NIA controls need evidence that staff are made aware of security and
trained. Today this is done outside Assayr. v0.5 lets an ISMS manager publish training courses (videos and
documents), attach a mandatory assessment, assign them to staff with due dates, and prove completion with a
report — fully on-premises, with no email server.

Success: a manager imports staff from CSV, creates a course with a Google Drive video and an uploaded PDF,
adds a 10-question assessment, assigns it to a department; employees sign in, see "My training", watch, pass
the assessment; the manager sees completion per department and exports an Excel completion report.

## Decisions (from the conversation)

- Staff take training with **Assayr accounts** (role `employee`); bulk creation by **CSV import**.
- Reminders are **in-app only** (no SMTP): employees land on "My training"; managers see overdue people.
- **Choice questions only** (single choice, multiple choice, true/false), marked automatically.
- **Retakes** (attempts per assessment, default 3) and **recurrence** (default 12 months; or one-off).
- Materials: **Google Drive links** (shown in Drive's preview player) **and uploaded files** on the server.

## Non-goals

Email or SMS reminders, written answers and manual marking, certificates, SCORM, video watch-time analytics.

## Staff accounts

- `User.department` (string, optional) and `User.must_change_password` (bool, default false).
- `POST /users/import` (platform admin, `users:manage`): CSV with header `name,email,department,role`
  (role optional, default `employee`; allowed: any existing role name). UTF-8 with or without BOM, comma or
  semicolon separated, max 1 MB / 2,000 rows. Existing emails are skipped and reported; invalid rows reported
  with line numbers; valid rows create active users with a random 16-character temporary password and
  `must_change_password = true`. Response lists created users with their temporary password **once** (never
  stored in plain text, never logged). Audited `user.import` (counts only).
- Sign-in with `must_change_password` returns the session with `must_change_password: true` in `/auth/me`;
  the frontend sends the user to a "Choose a new password" screen and every other API call except
  `/auth/me`, `/auth/logout` and `/auth/password` returns 403 "Change your temporary password first." until changed.
- Employees (users whose only role is `employee`) see a reduced navigation: **My training** only. Everyone
  with any role also gets "My training".

## Courses and materials

`Course` (per scope): `title`, `description`, `status` (`draft` | `published` | `archived`), `recurrence_months`
(int, nullable = one-off; default 12), `due_days` (default 30), `created_by`.

`CourseMaterial`: `course_id`, `sort_order`, `kind` (`drive` | `file`), `title`, `drive_url` (for drive),
`sha256`, `filename`, `mime`, `size` (for file).

- Drive links are validated: `https://drive.google.com/file/d/<id>/...` or `.../open?id=<id>`; stored as the
  file id; shown via `https://drive.google.com/file/d/<id>/preview` in an iframe. CSP adds
  `frame-src https://drive.google.com` (both `frontend/site.caddy` and the Windows Caddy template).
  The page notes that Drive videos need internet access on the viewer's computer.
- Uploads go to the existing blob store; allowed: mp4, webm, pdf, pptx, docx (sniffed); limit
  `training_upload_mb` setting, default 500. Served with `FileResponse` (HTTP Range for video), inline for
  video/pdf, attachment otherwise, `X-Content-Type-Options: nosniff`.
- A published course with assignments can't have materials or questions removed (409); a manager can
  archive it (no new assignments; existing ones remain visible).

## Assessment

One optional `Assessment` per course: `pass_mark` (percent, default 80), `max_attempts` (default 3),
`shuffle` (default true). `Question`: `kind` (`single` | `multiple` | `true_false`), `text`, `sort_order`,
options (`Option`: `text`, `is_correct`). Validation: single/true_false exactly one correct; multiple at
least one; 2–8 options (true_false fixed True/False).

`Attempt`: `assignment_id`, `started_at`, `submitted_at`, `answers` (JSON: question id → option ids),
`score` (percent), `passed`. Marking: a question scores 1 only if the chosen set equals the correct set.
The employee view never receives `is_correct`; after submitting it gets score, passed, and the ids of the
questions answered wrongly.

## Assignments

`Assignment`: `course_id`, `user_id`, `due_at` (date), `status` (`assigned` | `in_progress` | `passed` |
`failed`), `assigned_at`, `completed_at`, `extra_attempts` (int), `material_progress` (JSON list of
confirmed material ids), `source` (`all` | `department:<name>` | `role:<name>` | `user`).

- `POST /courses/{id}/assign` `{target: "all"} | {department} | {role} | {user_ids: [...]}, due_days?` —
  creates one assignment per matching active user who has no open assignment for the course.
- Overdue is derived (`due_at < today` and not passed), not stored.
- Materials: employee confirms each (`POST /my/assignments/{id}/materials/{material_id}/done`); the
  assessment unlocks when all are confirmed (a course without an assessment is passed when all are confirmed).
- Failed after `max_attempts + extra_attempts` attempts → `failed`; manager `POST /assignments/{id}/attempts`
  `{extra: n, reason}` re-opens it (audited).
- Recurrence: a daily job (existing jobs mechanism) creates the next assignment `recurrence_months` after
  `completed_at` for passed assignments of published courses; also assigns new users matching a
  department/role/all rule recorded on the course (`CourseRule`: `course_id`, `target`), so later joiners
  are picked up.

## Reporting

- `GET /training/summary`: per course — assigned, passed, in progress, overdue, failed, pass rate; per
  department completion %.
- `GET /courses/{id}/assignments` (manager): per person row (name, department, status, due, attempts, best score).
- `GET /training/report.xlsx`: sheet "Training completion": Name, Email, Department, Course, Assigned,
  Due, Status, Attempts, Score, Completed — attachable as evidence for A.6.3.

## Permissions

New `training:manage` for `isms_manager`. Every signed-in user can read and act on **their own**
assignments (`/my/...`). `employee` role gains no other permission. Managers can't see answers' raw
choices of other users, only scores.

## Screens

- **Training** (managers, nav group "Assure"): course cards with completion ring, "New course"; a course
  page with materials (add Drive link / upload, reorder), assessment editor (questions, options, correct
  answers, pass mark, attempts), status (publish/archive), assignment panel (all / department / role /
  people, due days), people table with filters (overdue, failed), "Grant attempts".
- **Dashboard**: a Training card (completion %, overdue count) for managers.
- **My training** (everyone): list of assignments with due/overdue badges; course player (materials in
  order with confirm buttons, Drive iframe or native video/PDF), assessment (one question per screen or
  all on one page — all on one page, with progress), result screen (score, pass/fail, retake if allowed).
- **Users**: "Import CSV" with a preview, a result table showing temporary passwords once with "Copy" and
  a warning to hand them out securely.
- **First sign-in**: "Choose a new password" screen.

## Migration

`0008_training.py`: `course`, `course_material`, `course_rule`, `assessment`, `question`,
`question_option`, `assignment`, `attempt`; `user_account.department`, `user_account.must_change_password`.

## Testing

API: CSV import (valid, duplicates, bad rows, BOM/semicolon, limits), forced password change gate, course
CRUD and publish rules, Drive URL validation, upload type/size, assessment validation, marking (single,
multiple, true/false), attempts exhaustion and extra attempts, assignment targets (no duplicates), material
gating, recurrence and joiner job, overdue derivation, summary numbers, report columns, permissions
(employee can't read others or manage). UI: import preview/result, password change, My training, player
gating, assessment submit and result, course editor, assign, summary.
