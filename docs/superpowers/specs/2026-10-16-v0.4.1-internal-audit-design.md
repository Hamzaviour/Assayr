# v0.4.1 — Internal audits (ISO 27001 and NIA) — design

Status: approved in conversation 2026-10-16. Builds on v0.4 (NIA catalogue, documents).

## Purpose

Internal auditors run ISO/IEC 27001 (clause 9.2) and Qatar NIA internal audits inside Assayr and hand over
the report in the organisation's existing workbook layout ("NIA - IA report"). Today the report is a
hand-maintained Excel sheet: one row per audited control with how it was tested and whether it passed.

Success: an auditor creates an audit, picks the controls, records test type and result per control, signs it
off, and exports an `.xlsx` that matches the existing workbook column-for-column. An existing workbook can be
imported into a new audit.

## Non-goals

- Audit results never change control status (status stays evidence-driven).
- No findings / corrective-action tracking (later release).
- No PDF export (Excel matches today's hand-over).
- No NCSA wording is shipped: the "assessment area" is the auditor's own text, stored per install.

## Data

`Audit` (per scope):
- `framework`: `iso27001` | `nia-2.1`
- `title` (e.g. "NIA internal audit 2026"), `period_start`, `period_end` (dates, optional)
- `auditor_id` (user), `scope_note`, `conclusion` (text, optional)
- `status`: `draft` → `in_progress` → `completed`; `completed_at`, `completed_by_id`
- A completed audit is read-only. An ISMS manager can reopen it (reason required, audited) → `in_progress`.
- `status` moves `draft` → `in_progress` automatically when the first result is recorded.

`AuditItem`:
- `audit_id`, `ref` (ISO control code like `A.5.1`, or NIA ref like `SU 5`), `sort_order`
- `domain`, `sub_domain` (strings; prefilled, editable). ISO: domain = Annex A theme (or "Clauses"),
  sub-domain = theme. NIA: domain = NIA domain name, sub-domain = domain name (our catalogue has no
  sub-domains; the auditor or an import sets it).
- `assessment_area` (text, auditor's wording; empty by default)
- `test_type`: `DA` | `OEA` | `Both` | null
- `requirement`: `M` | `A` | null (NIA prefilled from the mandatory flag: M if mandatory else A; ISO null)
- `result`: `pass` | `fail` | `partial` | `na` | null (null = not yet tested)
- `notes` (text)
- unique `(audit_id, ref)`

Refs are validated against the framework's catalogue when added (ISO: controls in scope excluding `NIA `
own controls; NIA: NIA control refs).

## Workbook export / import

Export (`GET /audits/{id}/export.xlsx`): one sheet named `NIA - IA report` (NIA) or `ISO - IA report` (ISO),
header row exactly:

`Sr. No.` | `Domain Name` | `Sub Domain Name` | `NIA Control` (ISO: `ISO Control`) |
`Control Description/Assessment Area` |
`Design Assessment (DA) / Operating Effectiveness Assessment (OEA) / Both` |
`Mandatory (M) / Additional (A)` | `Control status (Pass/Fail/Partial)`

Rows in item order; Sr. No. 1..n; result written as `Pass` / `Fail` / `Partial` / `NA` / blank.

Import (`POST /audits/import`, multipart `.xlsx`, framework given): reads the first sheet, finds the header
row by the `Control status` column, maps columns by header text (case-insensitive, whitespace-tolerant), and
creates a new draft audit (`in_progress` if any result present). Values normalised: test type `both` →
`Both`; result `Pass/Fail/Partial/NA` (case-insensitive), anything else → null. Rows whose control ref is not
in the catalogue are skipped and returned in `unknown_refs`; duplicate refs keep the first. Max 5 MB,
max 2,000 rows; a file without the expected header is refused (422) and nothing is created.

## API

- `GET /audits` (list with counts: total, tested, pass, partial, fail, na)
- `POST /audits` `{framework, title, period_start?, period_end?, auditor_id?, scope_note?}`
- `GET /audits/{id}` (detail with items), `PATCH /audits/{id}` (title, period, auditor, scope note, conclusion)
- `POST /audits/{id}/items` `{refs: [...]} | {all: true} | {domain: "<code or theme>"}` — adds, skips existing
- `PATCH /audits/{id}/items/{item_id}` (domain, sub_domain, assessment_area, test_type, requirement, result, notes)
- `DELETE /audits/{id}/items/{item_id}`
- `POST /audits/{id}/complete` (needs every item to have a result; otherwise 409 listing the count untested)
- `POST /audits/{id}/reopen` `{reason}` (ISMS manager only)
- `GET /audits/{id}/export.xlsx`, `POST /audits/import`

Permissions: new `audits:write` for `isms_manager` and `internal_auditor`; reading needs `controls:read`.
Writes to a completed audit → 409 "This audit is completed. Reopen it to make changes." All writes audited
(`audit.create`, `audit.items`, `audit.result`, `audit.complete`, `audit.reopen`, `audit.import`).

## Screens

- Nav "Audits" (today "soon") → `/audits`: list of audits (framework, title, period, auditor, status,
  progress tested/total, Pass/Partial/Fail stacked bar), "New audit" for `audits:write`, "Import workbook".
- `/audits/$id`: summary header (framework, status, progress, result bar, Complete / Reopen / Export Excel),
  "Add controls" (all, by domain/theme, or by ref), table grouped by domain: ref (links to the ISO or NIA
  control page so evidence is one click away), assessment area, test type, M/A, result (select), notes;
  filters: All / Untested / Fail & Partial. Read-only when completed or for users without `audits:write`.
